How to Get a 90+ PageSpeed Score Without Breaking Your Design

📅 Apr 8, 2025
⏱ 9 min read
✍️ Divyam Jain

A 90+ PageSpeed score isn't just a vanity metric. It's a ranking factor, a conversion factor, and a direct measure of how much you respect your visitors' time. The good news: most sites can hit 90+ without any significant design compromise. The bad news: it takes deliberate technical work that most developers skip.

Here's exactly how I do it on every site I build.

Step 1 — Fix Your Images First (Biggest Win)

Images are responsible for the majority of page weight on almost every website I audit. Three changes fix most of the problem:

  • Convert everything to WebP. WebP files are typically 25–35% smaller than equivalent JPEGs and PNGs with no visible quality loss. Use Squoosh (free, browser-based) or an automated build step.
  • Set explicit width and height on every image tag. This prevents Cumulative Layout Shift (CLS) — the annoying page jump as images load. Add width="800" height="600" directly in the HTML.
  • Lazy load below-the-fold images. Add loading="lazy" to any image that isn't in the initial viewport. Your hero image should have loading="eager" (or no attribute).

Quick test: Run your site through PageSpeed Insights right now. If "Serve images in next-gen formats" or "Properly size images" appears in the opportunities section, images are your biggest problem. Fix this first — it typically accounts for 15–25 points of score improvement alone.

Step 2 — Eliminate Render-Blocking Resources

Render-blocking resources are CSS or JavaScript files that force the browser to stop building the page until they've finished loading. Every render-blocking resource adds to your Largest Contentful Paint (LCP) time.

  • Move all non-critical JavaScript to the bottom of the body, or add defer or async attributes
  • Inline critical CSS (the styles needed to render what's visible above the fold) directly in the <head>
  • Load non-critical CSS asynchronously using rel="preload" with as="style"
  • Remove any unused JavaScript libraries — jQuery is often loaded and barely used

Step 3 — Optimise Google Fonts Loading

Google Fonts are a render-blocking resource by default. Most sites load them incorrectly and lose 5–10 PageSpeed points as a result.

  • Add rel="preconnect" tags for both fonts.googleapis.com and fonts.gstatic.com before your font link tag
  • Add display=swap to your Google Fonts URL so text renders in a fallback font while the web font loads
  • Only load the font weights you actually use — don't load all 9 weights if you only use 400 and 700
  • Consider self-hosting fonts to eliminate the third-party DNS lookup entirely

Step 4 — Enable Compression and Caching on Your Server

If you're on a decent host, most of this is automatic. If you're not sure, check:

  • Gzip or Brotli compression is enabled — text files (HTML, CSS, JS) should be compressed before sending
  • Cache-Control headers are set appropriately — static assets (images, CSS, JS) should cache for at least 1 year
  • You're using a CDN if you have international visitors — Cloudflare's free tier is sufficient for most small sites

Step 5 — Reduce Third-Party Scripts

Every third-party script — chat widgets, analytics, ad trackers, social embeds — adds load time and is outside your control. Audit what's running on your site:

  • Replace heavy analytics (Google Analytics 4 with GTM) with lightweight alternatives like Fathom or Plausible for non-critical sites
  • Load chat widgets only when the user scrolls toward the bottom of the page
  • Replace social embed widgets with static screenshots linked to the original post
  • Remove any scripts you're not actively using — they tend to accumulate

Work through these five steps in order and most sites hit 90+ without touching the design at all. The design doesn't cause slow pages — unoptimised assets and careless resource loading do.
